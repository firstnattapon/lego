🧱 CODE TOUR • lego-firebase

เข้าใจระบบแบบ
โรงงาน LEGO อัตโนมัติ

Scheduler ปลุกระบบ → อ่านเวลาตลาด → อ่านราคาและ holdings → เปิด/ปิด gate ด้วย DNA → สร้างแถว 17 คอลัมน์ → commit ลง Firebase → ส่งคำสั่งผ่าน worker อีกตัวหนึ่ง

⏱ เครื่องจักรเวลา DNA
lego_one_row: clock → snapshot → decision → row → commit → outbox
📦 เครื่องจักรคำสั่งซื้อขาย
lego_order_worker: outbox → guards → preview → place → fill → realized
ภาพรวมไฟล์ลองตัดสินใจลองสมการ17 คอลัมน์RTDBSafetyสถานะQuiz

1. เดินชมโรงงานทีละสถานี

กดสถานีเพื่อดูว่าเกิดอะไรขึ้น

แนวคิดสำคัญ: commit แถวของโมเดลก่อน แล้วค่อยสร้าง outbox intent ดังนั้น broker ช้าหรือ timeout จะไม่ rollback แถวและไม่กิน DNA step ซ้ำ

6. RTDB คือโกดังหลายชั้น

  • webull_lego_rows/ — แถว 17 คอลัมน์ตาม run_id
  • webull_lego_state/ — anchor, version, step, slot, fingerprint
  • webull_lego_order_outbox/ — intent รอส่ง/รอตรวจ
  • webull_lego_order_audit/ — ประวัติคำสั่งที่ตัดข้อมูลลับ
  • webull_lego_realized/ — open legs, applied fills, realized cumulative
  • webull_lego_errors/ — error และ trace แบบจำกัด

7. Safety Guards

🔁 Idempotency
run_id เดิมไม่สร้างผลซ้ำ
🧱 One slot, one row
slot เดิมตอบ SLOT_CONSUMED
⚓ Stale anchor
version ไม่ตรง ห้ามเขียนทับ
📅 Calendar fingerprint
เวลาเปลี่ยนจน DNA เสี่ยงเลื่อน phase จะหยุด
➡️ Monotonic ordinal
DNA time ต้องเดินหน้า
🧪 UAT-only
ส่งอัตโนมัติได้เฉพาะ Test (UAT)
👀 Preview gate
preview ไม่ผ่าน ไม่ place
✅ Fill จริงเท่านั้น
SUBMITTED ยังไม่ใช่ realized
🚦 Active order
มี order เปิดอยู่ จะ suppress
📏 Holdings drift
position เปลี่ยนจากตอนตัดสินใจ จะไม่ส่ง intent เก่า

8. อ่าน pipeline_status

สถานะความหมาย
ROW_COMMITTEDcommit สำเร็จหรือ idempotent
MARKET_CLOSEDนอก regular session/วันหยุด
SLOT_CONSUMEDslot นี้มีแถวแล้ว
STALE_ANCHORstate เปลี่ยนก่อน invocation นี้ commit
CALENDAR_DRIFTกฎเวลาไม่ตรง chain เดิม
ORDINAL_REGRESSIONmarket ordinal กำลังเดินถอย
CONFIG_ERRORLEGO_SLOT_SECONDS หาย/ไม่รองรับ
SNAPSHOT_OR_ENGINE_ERRORดึงข้อมูลหรือคำนวณล้มเหลว
