## Step 3 — 5-Whys (P1) และฝั่งเรา / ฝั่ง Webull

- **R1 / `leaps_value` (ฝั่งเรา)**
  - live release ที่ไม่มีวันส่ง order ได้ deploy ได้ ← release-plan ไม่มี finding เรื่อง LEAPS ← `ReleaseInputs` ไม่มี `leaps_shares` ← PR #43 ใส่ LEAPS เข้า binding แต่ไม่ได้ใส่ใน `release_horizon` และเตือนไว้แค่ในเอกสาร
  - **ต้นตอ**: gate ไม่คำนวณ FIX_C − LEAPS × P
- **R4 / CANDIDATE_MISMATCH (ฝั่งเรา; สาเหตุจริงของครั้งก่อน "ไม่ทราบ")**
  - hash ที่ deploy ≠ commit ← `candidate_manifest` เดิน filesystem ⇒ รวมไฟล์ที่ git ignore แต่ชนิดไฟล์อยู่ในรายการ (`token.txt`, `*credentials*.json`, `venv/`, `.mypy_cache/*.json`, `.ruff_cache/.gitignore`) และ `../lego-firebase-streamlit` ← `git status --porcelain` ไม่แสดงไฟล์ ignored ← upload ใช้ `--source=.`
  - **ต้นตอ**: hash ไม่ได้ระบุทั้ง commit และไฟล์ที่ upload
  - สอดคล้องกับลำดับเหตุการณ์: 00004 deploy จาก clone ใหม่ตาม audit 31 ต.ค. ⇒ ตรง; 00005 deploy ด้วย `git pull` ใน `~/lego` เดิมตามเอกสาร LEAPS ⇒ ไม่ตรง
  - sandbox ทำซ้ำกลไกได้: script เดิม + ไฟล์ ignored ⇒ hash ต่างจาก commit และ candidate ที่รีวิวแล้วถูกปฏิเสธ (fail-first ข้อ Step 5)
  - เก็บหลักฐานสาเหตุจริงได้ตามหัวข้อคำสั่ง
- **R3 / R5 / R6 / R7 (ฝั่งเรา)**
  - release ถูกตัดสินจาก config อย่างเดียว ไม่ได้ดูบัญชีจริง ← ไม่มีเครื่องมืออ่านบัญชีก่อน deploy นอกจาก smoke ที่ไม่ตัดสินเศรษฐศาสตร์ของ release
  - **ต้นตอ**: ไม่มี gate ระหว่าง plan กับ deploy ที่เทียบ release กับบัญชีจริง
- **R2 / R9 / ประเภทบัญชี (ฝั่ง Webull, "ไม่ทราบ")**
  - เอกสารไม่ระบุกติกา fractional, การ settle และรูปแบบ fee ของ fill จริงบน PROD
  - เก็บหลักฐานได้จาก canary ใบแรก (Order Detail + position) และคำตอบเป็นลายลักษณ์อักษรจาก Webull
  - ระหว่างที่ยังไม่ทราบ ระบบ fail closed (`AWAITING_FILL_CONFIRMATION` / `AWAITING_BROKER_FEE` ⇒ หยุดรับ order ใหม่)

## Go / No-Go (เจ้าของระบบ)

**GO เมื่อครบทุกข้อ:**

1. PR merged + CI เขียว; deploy จาก clone ใหม่
2. G4: ตั้ง webhook แล้ว `python3 ops.py alert-drill --secret projects/lego-firebase/secrets/<ชื่อ> --send` และ **มีคนได้รับจริง**
3. Webull ยืนยันเป็นลายลักษณ์อักษร:
   - ประเภทบัญชี (cash / margin)
   - การ settle / good-faith เมื่อซื้อขายวันเดียวกัน
   - บัญชีเปิด fractional แล้ว
4. ในแอป: ถือ QBTS long CALL ≥ 1 สัญญา (หมดอายุหลัง window ≥ 60 วัน); หุ้นจริงอยู่ในช่วงที่ preflight บอก; ไม่มี open order ของ QBTS
5. USD buying power ≥ **$1,515**
6. ราคา QBTS < $15 (ควร < $14.50)
7. preflight และ release-plan ไม่มี BLOCK; อ่าน WARN ทุกข้อ (`fractional_policy`, `fee_unmeasured`, `leaps_value`)
8. อ่านค่าทุกตัวในผลรอบแรก (symbol, caps 20 / 150 / 10, window, prefunded) แล้วจึงใส่ ack
9. หลัง deploy: `verify_deployment` PASS, `python3 ops.py status` ไม่มี fence / halt / inflight, DB ยังตอบ `Permission denied`
10. คนเฝ้า session แรกตั้งแต่ 21:30 เวลาไทย
