## F-b / F-c — ข้อจำกัดของกฎ UAT PENDING ที่ทราบอยู่แล้ว (ไม่แก้ใน PR นี้)

`docs/AUDIT_20261013_TH.md` (ตรวจรอบสาม) บันทึกไว้แล้วว่ากฎปล่อย zombie ต้องมี `cancel_refused_at` ซึ่งตั้งเฉพาะเมื่อ broker ตอบ 417 ชัดเจน:
ถ้า cancel ได้ผล "ไม่ทราบ" (timeout หรือ `TickDeadlineExceeded`) `expiry_candidate()` / `expiry_proof_blockers()` ไม่ผ่าน และ `read_failed()` หลัง grace 120 s ⇒ `CANCEL_CONFIRMATION_OVERDUE` ⇒ `MANUAL_RECONCILIATION_REQUIRED` + operator halt
(ซึ่งเกิดราว 7 นาทีหลัง Place — เร็วกว่าเกณฑ์ 30 นาทีของกฎ UAT จึงแก้ด้วยการขยายเงื่อนไขอย่างเดียวไม่พอ ต้องแก้ `read_failed` และ `execution_service.py` ด้วย)

- **เหตุที่ไม่แก้**: ยังไม่เคยเกิดใน zombie 5 ตัว (4 ตัวตาม audit 13 ต.ค. + `7448c833`; ตัวนี้ได้ 417 ชัดเจน) — ไม่เคยเห็น "zombie + cancel timeout" พร้อมกัน; การแก้แตะ recovery logic ซึ่งผู้ใช้กำหนดไว้นอกขอบเขตรอบนี้ (เครื่องมือ + เอกสาร) และ PROD ไม่โดน (นโยบาย `hold`, ไม่ cancel)
- **หลักฐานใหม่รอบนี้**: cancel timeout เกิดจริง 1 ใน 4 ครั้ง (บน order SUBMITTED ซึ่งถูก cancel จริงและฟื้นใน 59 s) ⇒ ผลลัพธ์ "ไม่ทราบ" ไม่ใช่เรื่องสมมติ; ตัวอย่างเล็กเกินประเมินความถี่ของเหตุการณ์ร่วม — **ไม่ทราบความถี่**
- **F-c (ทฤษฎี)**: zombie สถานะ `SUBMITTED` + cancel ถูกปฏิเสธ — กฎ UAT รับเฉพาะ `PENDING` (`stuck_release_requires_pending`) ⇒ hold 8 ชม. ⇒ halt; ไม่เคยเห็น zombie เป็น `SUBMITTED`
- **ถ้าเกิด**: tick เป็น `MANUAL_RECONCILIATION_REQUIRED` แล้วเป็น `OPERATOR_HALT` (webhook ส่งได้ทั้งสอง status เมื่อมี receiver: ตัวแรกมีอยู่เดิม ตัวหลังเพิ่มใน C1).
  ถ้า order ยัง non-terminal ที่ broker **ไม่มีเครื่องมือปล่อย**: `--expiry-proof` ถูกบล็อกด้วย `cancel_not_refused` และ `clear-operator-halt` ปฏิเสธขณะ fence ยังมี order ค้าง ⇒ ต้องรอให้ broker retire order แล้วกู้แบบ terminal
  (zombie 8 ต.ค. หายภายในไม่กี่วัน แต่ 12 ต.ค. ยังค้างหลังปิดตลาด 2 ชม.) ⇒ **เทรดหยุดได้หลายวัน** ถ้าเกิด — จึงเป็นเหตุผลที่ควรมี PR แยก; ขั้นตอนอยู่ในหัวข้อ "เมื่อ UAT หยุดเพราะ order ค้าง" ของ `docs/PROD_LIVE_RUNBOOK_TH.md`
- **ร่างทางแก้ (PR แยก ถ้าผู้ใช้สั่ง)**: ให้ UAT ถือ order `PENDING` ที่ cancel ไม่ทราบผลจนถึงเกณฑ์ 30 นาทีก่อนปล่อย ภายใต้เงื่อนไข proof เดิมครบ (broker ยัง list `PENDING` filled 0 แถวเดียว, holdings ไม่เปลี่ยน)
