## สิ่งที่แก้ใน source

**Change 1 — DAY-expiry proof (N1)**
- `recovery_policy.py`: `LEGO_STALE_ORDER_ACTION` รับ `cancel_expire` เพิ่ม (cancel เหมือน `cancel` + ปล่อยเมื่อพิสูจน์ได้); ค่า default และ PROD ยัง `hold`;
  มีเพียง `action` ที่เปลี่ยน fingerprint ของ policy ใหม่ — policy `cancel` เดิม (`e583ee78…`) และ intent ที่ค้างอยู่ไม่เปลี่ยน hash (เทสต์ล็อก)
- `config.py`: PROD + `cancel_expire` → `ConfigurationError` ("UAT only")
- `order_recovery.py`: `expiry_proof_blockers()` (pure — read ทั้งหมดส่งเข้ามา, ไม่ import `webull_io`) ต้องผ่านพร้อมกันทุกข้อ:
  Place แล้ว + cancel ถูกปฏิเสธ; payload เป็น leg เดียว MARKET/DAY/CORE; ผ่านปิด session ของ NY ที่ order ถูกวาง + 1 ชั่วโมง (`session_bounds` รวม early close);
  broker evidence ตรง identity/quantity; สถานะ `PENDING`/`SUBMITTED` และ filled_quantity = 0 ที่อ่านได้ชัดเจน (สถานะ `UNKNOWN` ไม่นับ);
  อ่าน open orders ครบและไม่มี order นี้; holdings เท่า `decision_holdings` ภายใน tolerance. `expiry_release()` คืน summary `EXPIRED` zero-fill ที่คง `broker_status=PENDING`
  (ไม่อ่านเป็น broker expiry) พร้อม `terminal_reason=DAY_EXPIRY_PROOF`, hash ของ proof; `handle()` ไม่ประทับ `cancel_confirmed_at` ให้ order ที่ปล่อยด้วย proof
- `execution_service.py` `_dispatch_or_reconcile_one`: ก่อน `handle()` ถ้า intent เข้าเงื่อนไข (`expiry_candidate`: policy `cancel_expire` หรือคนยืนยัน + ผ่านปิด session + margin)
  อ่าน open orders + holdings (งบ ≥10 วินาที, ล้มเหลวใด ๆ = hold ต่อ) แล้วใช้ summary ที่ปล่อย — ผ่านเส้นทาง terminal เดิม (`_finish_with_realized`, `_chain_fence_can_clear`):
  ไม่ลง cashflow/FIFO, reject circuit ไม่นับ, fence ปล่อย, ไม่ halt; บันทึก `day_expiry_released` ใน warnings + log; ไม่อ่าน broker เลยระหว่างเวลาเทรด
- `tools/resume_order_reconciliation.py --expiry-proof`: dry run อ่าน order/open orders/holdings พิมพ์ blockers หรือ `RELEASE-EXPIRED <sha>`; `--confirm` re-arm intent
  (`PLACING_UNKNOWN`, `reconcile_resume.expiry_proof_authorized`) — **ไม่ปล่อย fence ไม่ปลด halt** worker จะพิสูจน์ซ้ำเองก่อนปล่อย; ใช้ได้กับ PROD เพราะคนยืนยัน

## ข้อจำกัดที่ต้องรู้

- การปล่อยต้องรอให้ session จบ + 1 ชั่วโมง จึง**ไม่ช่วย session ที่ order ค้าง** (รอบนี้เสีย 16 slot) — ช่วยไม่ให้ halt ข้ามไป session ถัดไปและไม่ต้องใช้คน
- ถ้า order ที่ปล่อยไปแล้วถูก fill ทีหลัง ระบบ**ไม่ตรวจพบโดยเฉพาะ**: `check_holdings_continuity` ปฏิเสธเฉพาะ position หายเป็น 0 และ drift check เทียบ decision กับ dispatch ของ order เดียวกัน;
  ledger โมเดล (Aₙ/Eₙ) จะขาด fill นั้นขณะ position จริงเปลี่ยน — ลดความเสี่ยงด้วย margin 1 ชั่วโมง, เงื่อนไข open orders/holdings และ caps (30 หุ้น / 1,500 USD);
  นี่คือเหตุผลที่ PROD ต้องให้คนยืนยัน
- ความหมายของ `PENDING` หลังปิดตลาดและของ 417 อนุมานจาก log UAT เท่านั้น (เข้าเอกสาร Webull ไม่ได้) — proof จึงตั้งเงื่อนไขหลายข้อพร้อมกันและ fail ไปทาง hold
- ถ้าบัญชี UAT (บัญชีแชร์) เปลี่ยน position จากแหล่งอื่น proof จะไม่ผ่าน (`holdings_changed`) → hold/halt เหมือนเดิม
- N3 (งบ tick), N4 (alert), N5 (สาเหตุ broker), N6 (fee/edge) ยังเปิดอยู่; ผมรัน broker ไม่ได้ในสภาพแวดล้อมนี้
- gate/acknowledgement เป็น review checkpoint ไม่ใช่ security boundary เชิงเข้ารหัส (ดู `docs/AUDIT_20261005_TH.md`) — `reconcile_resume.expiry_proof_authorized` ก็เช่นกัน และ worker พิสูจน์ซ้ำเสมอ
