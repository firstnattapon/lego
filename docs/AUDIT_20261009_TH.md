## ข้อจำกัดที่ต้องรู้

- **recorder ยังไม่เคยรันกับ RTDB และ Webull จริง**: ขนาด/ความหน่วงของการเขียน (ประมาณ 0.5–1 MB/วัน, ≤3 วินาทีต่อ tick, checkpoint หลัง Place/Cancel อีกครั้ง) เป็นการประเมิน ยังไม่ได้วัด —
  ดู `heartbeat.flush_timeouts`/`write_errors` หลัง deploy; สั่ง `LEGO_TRACE_LEVEL=off` ปิดได้ทันที
- recorder เป็น best effort: "ไม่มี trace" ไม่ได้แปลว่า "ไม่มีเหตุการณ์"; order ที่ค้างอยู่ก่อน deploy ไม่มี trace ย้อนหลัง (ใช้ dry run ข้อ 2)
- digest ที่ได้จากหลักฐานรอบนี้บอก**ว่าอะไรไม่รู้** ไม่ได้เติมให้ — โดยเฉพาะ N1/N2; ความหมายของ `PENDING` หลังปิดตลาดและของ 417 ยังเป็นข้อสันนิษฐานจน Webull ยืนยัน
- ระบบมองไม่เห็นถ้า order ที่ถูกปล่อยด้วย proof ถูก fill ภายหลัง (ข้อจำกัดเดิมของ audit 7 ต.ค. — ลดด้วย margin 1 ชั่วโมง, เงื่อนไข open orders/holdings และ caps)
- ผมรัน broker ไม่ได้ในสภาพแวดล้อมนี้ และ CI (Python 3.12, emulator, gitleaks, pip-audit) ยังไม่รันตอนเขียนเอกสารนี้

**สถานะส่งมอบ:** source/PR เป็นส่วนที่ตรวจได้ในงานนี้; UAT endurance และ PROD live gates ยัง BLOCKED
ไม่มีการ deploy, Place, Cancel, resume, เปลี่ยน quota หรือ clear halt ที่บัญชีจริงในรอบนี้
