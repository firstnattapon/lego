## สาเหตุและการแก้

1. **Account identity validation:** runtime เดิมสร้าง client โดยไม่ตรวจ account list;
   smoke เดิมยอมรับ `account_number`/`account_no` หรือ account ID ใน object ที่ซ้อนผิดรูป
   ทำให้รายงานบัญชีผ่านทั้งที่ไม่ใช่ ID สำหรับ API
   แก้ให้ยอมรับเฉพาะ `account_id` string ที่ตรงในรายการบัญชีที่ authenticated;
   ปฏิเสธรายการผิดรูป, error envelope และ duplicate ID
   ตรวจเมื่อสร้าง/ต่ออายุ client cache และก่อนนำ client ไปใช้
   cache ผูก credentials, environment, account และ TTL เดิม
   หากตรวจไม่ผ่าน จะไม่สร้าง client cache ที่ใช้งานได้และไม่เดาบัญชีอื่นแทน
2. **Incomplete smoke:** เพิ่ม instrument capability และ USD buying power reads
   ให้การทดสอบครอบคลุมข้อมูลที่ money path ต้องใช้ก่อน Preview/Place
   ยังคงไม่ส่ง Place; Preview ต้องร้องขอโดยชัดเจนและเป็น UAT เท่านั้น
3. **Opaque incident diagnostics:** completion เดิมบอกเพียง exception class
   และไม่แสดง error metadata ของ execution result แต่ละรายการ
   เพิ่ม operation, HTTP status, known broker error code และ UUID request ID
   ลง decision/execution error และ completion event โดยตรวจ allowlist อีกครั้งก่อน log
   ข้อความ error และ raw broker payload ไม่ถูกคัดลอกเข้า structured event
4. **Duplicate/log credential handling:** หยุด SDK propagation ไป root handler
   และปิดช่องที่ `Authorization: Bearer ...` ถูกปิดบังเพียงคำว่า Bearer
   เพิ่ม token, app secret, account number และ exception traceback redaction

**การแก้เหล่านี้ไม่ได้พิสูจน์ว่า HTTP 417 ของ broker หายแล้ว**
สเปก Thailand ที่ตรวจสดวันที่ 17 กันยายนยังระบุ
`GET /trading/assets/positions/list`, version v3 ตรงกับ SDK 3.0.1 ใน log
จึงไม่มีหลักฐานรองรับการเปลี่ยนกลับ route เก่า หรือเปลี่ยน signing algorithm เอง
account mismatch เป็นสิ่งที่ต้องตรวจแยกจาก broker outage ไม่ใช่ root cause ที่ยืนยันแล้ว
retry ของ safe reads ยังมีเพดานเดิม; Place ยังคงไม่ retry อัตโนมัติ

## งานที่ต้องผ่านก่อนเปิดเงินจริง

1. โหลด credentials ของ environment ที่ตั้งใจใช้อย่างปลอดภัย ตรวจบัญชีด้วยคำสั่ง
   `AUTO_SUBMIT=false python lego_broker_smoke.py` ใน shell ที่รองรับ syntax นี้
   บน PowerShell ใช้ `$env:AUTO_SUBMIT='false'; python lego_broker_smoke.py`
   smoke เป็น broker reads; ไม่เรียก `lego_tick` ซึ่งอาจส่งออเดอร์ตาม deployment config
   หาก account mismatch ให้แก้ secret ให้เป็น account_id ที่ถูกต้อง ห้ามเลือกบัญชีแรกอัตโนมัติ
2. หาก account check ผ่านแต่ positions ยังตอบ 417 ให้เก็บเวลา UTC, operation,
   HTTP code และ request ID ส่งให้ Webull ตรวจ service/account entitlement
   ห้ามใช้ holdings=0 ทดแทน error และห้ามส่ง Place เพื่อทดสอบว่าปัญหาหายหรือไม่
3. สร้าง candidate manifest และ release binding ใหม่จาก source ที่จะ deploy จริง
   ทดสอบ UAT ที่ได้รับอนุมัติ: Preview → Place → terminal fill/fee → holdings/cashflow
   รวม restart ระหว่างผล Place ไม่ชัดเจน, partial fill, late fee และ repeated reconciliation
   ต้องไม่มี duplicate order/ledger delta และไม่มี manual fence ที่ค้างโดยไม่แจ้งเตือน
4. พิสูจน์ IAM/OIDC, rules, alerts, token rotation และ restore กับ deployment จริง
   soak อย่างน้อยหนึ่ง regular session ที่ครบและหนึ่ง cold start/recovery
   เฝ้าดู completion error, missed ticks, fee backlog และ DNA headroom
   account-list guard เพิ่มหนึ่ง read ต่อ client rebuild จึงต้องนับใน quota/latency ด้วย
5. Production ต้องมี account-specific evidence และ authorization ของ candidate นั้น
   การทดสอบ local/CI หรือชื่อ service ว่า UAT ไม่ใช่การรับรองเงินจริง
